# DSS Low-fi Wireframe

**프로젝트**: 동성실리콘 Digital Transformation  
**작성일**: 2026-03-28  
**문서 유형**: Low-fidelity Wireframe 초안 (구조·흐름 검증용)

---

## 1. Wireframe 설계 원칙

1. **흐름 우선**: 주문 → 생산 → 출하의 단방향 업무 흐름이 화면 구조에 직접 반영된다. 사용자가 다음 단계로 어떻게 넘어가는지 화면마다 명확히 드러나야 한다.
2. **데이터 테이블 중심**: 목록 화면은 Carbon Data Table 패턴을 기반으로 한다. 검색·필터·배치 액션은 테이블 상단에 일관된 위치로 배치하며, 카드·타일·그리드 레이아웃은 사용하지 않는다.
3. **정보 위계 명확성**: 각 화면은 페이지 타이틀 → 필터/액션 바 → 데이터 영역의 3단 구조를 기본으로 한다. 상세 화면은 섹션 헤더로 정보 그룹을 명확히 구분한다.
4. **권한 기반 액션 노출**: 입력·수정·취소·전달 액션은 권한이 있는 역할에게만 활성화된다. 비활성 상태(disabled)로 숨기지 않고 렌더링 자체를 생략하는 방향을 우선한다.
5. **경량 폼 설계**: 입력 화면은 label + input + helper text의 Carbon Form Group 단위로 구성한다. 설계번호 조회처럼 연동 입력이 있는 경우 자동 채워지는 필드는 read-only로 시각적으로 구분한다.
6. **모바일 고려, 과설계 금지**: PC 우선이되 반응형 레이아웃을 전제한다. Low-fi 단계에서 픽셀 단위 배치나 색상·타이포그래피 지정은 하지 않는다. 구조와 정보 배치만 검증한다.

## 2. 공통 레이아웃

### 내비게이션 구조

좌측 고정 사이드바(Carbon UI Shell Left Panel). 메뉴 depth는 최대 2단.

```
[사이드바]
  DSS
  ─────────────
  주문
    주문 입력        ← A만 노출
    주문 현황        ← A, P, E 노출
  생산 (후속)
    생산 현황        ← 후속 확장 시 P, E 노출
  출하 (후속)
    출하 현황        ← 후속 확장 시 A, P, E 노출
  기준정보
    설계 관리        ← A, E 노출
    고객 관리        ← A, E 노출
  ─────────────
  [사용자명 / 역할]
  [로그아웃]
```

- 역할에 따라 접근 불가 메뉴 항목은 렌더링되지 않는다.
- 현재 활성 메뉴 항목은 강조 표시(Carbon active state).
- 모바일에서는 사이드바가 접혀 햄버거 메뉴로 전환된다.

### 페이지 헤더 구조

```
+----------------------------------------------------------+
| [페이지 타이틀]                                           |
| [보조 설명 — 이 화면의 목적 1줄]                          |
+----------------------------------------------------------+
```

- 타이틀은 Carbon PageHeader 패턴 기준.
- 보조 설명은 화면 목적을 짧게 명시한다 (예: "등록된 전체 주문의 진행 상태를 확인합니다").

### 콘텐츠 영역 구조

목록 화면 기본 구조:

```
[필터/검색 바]
  검색 입력 | 필터 드롭다운(들) | [배치 액션 버튼] | [주요 CTA]

[데이터 테이블]
  체크박스 | 컬럼1 | 컬럼2 | ... | 상태 | 액션
  ...

[페이지네이션]
```

상세/입력 화면 기본 구조:

```
[섹션 헤더]
  [폼 그룹 / 정보 그룹]

[섹션 헤더]
  [폼 그룹 / 정보 그룹]

[하단 고정 액션 바]
  [취소]  [저장 / 확인]
```

### 공통 액션 배치 원칙

- **주요 CTA(신규 입력, 저장 등)**: 검색/필터 바 우측 끝 또는 하단 고정 액션 바 우측.
- **배치 액션(취소, 전달 등)**: 테이블 상단, 항목 선택 시에만 활성화.
- **행 단위 액션**: 테이블 행 우측 overflow menu(케밥 메뉴) 또는 인라인 버튼. 단순한 경우 인라인 버튼 사용.
- **파괴적 액션(취소)**: 반드시 확인 모달(Danger Modal) 경유.

### 권한별 노출 차이 기본 원칙

| 역할 | 노출 원칙 |
|------|-----------|
| A — Administrative (사무직) | 주문·설계·고객의 입력·수정·취소·전달 액션 활성화. 생산 공정 단계 변경 불가. |
| P — Production (현장직, 팀장 포함) | POC에서는 생산중 주문 조회 중심. 후속 확장에서 생산 공정 단계 변경, 출하 실적 입력 활성화. 주문·설계·고객 데이터 수정 불가. |
| E — Executive (임원) | 모든 목록·상세 조회 가능. 모든 입력·수정·취소·전달 액션 미표시. |

## 3. 화면별 Low-fi Wireframe

---

### 주문 입력

#### 화면 목적
이메일·카카오톡·전화로 수신된 발주를 사무 인력이 웹 화면에서 직접 입력한다. 설계번호 조회로 제품 사양을 자동으로 불러오고, 출하예정일을 날짜별로 분할 입력한다.

#### 주요 사용자
- A — Administrative (사무직)

#### 화면 구성

**상단**: 페이지 타이틀 + 보조 설명

**중단 — 폼 영역 (2개 섹션)**

섹션 1: 주문 기본 정보
- 고객명 (검색 선택 — Combobox)
- 설계번호 (텍스트 입력 → 조회 버튼 → 아래 필드 자동 채워짐)
- 업체명 / 품명 / 규격 / 부서코드 (read-only, 설계번호 조회 결과)
- 발주 수량 (숫자 입력)
- 발주 채널 (Select — 이메일 / 카카오톡 / 전화)

섹션 2: 출하예정일
- 행 단위 입력 테이블: 예정일 | 예정수량 | [행 삭제]
- [+ 출하예정일 추가] 버튼으로 행 추가

**하단**: 고정 액션 바
- [취소] [주문 저장] (저장 후 → 주문 현황으로 이동)

#### 포함 컴포넌트 (개념 수준)
- 페이지 타이틀
- Form Group (label + input + helper text)
- Combobox (고객 검색 선택)
- Text Input (설계번호)
- Button — secondary (설계번호 조회)
- Read-only Text Field (자동 조회 결과 필드)
- Number Input (발주 수량)
- Select (발주 채널)
- Section Header (섹션 구분)
- Inline Editable Table (출하예정일 행 입력)
- Button — ghost (행 추가)
- Button — primary (저장)
- Button — secondary (취소)

#### ASCII Wireframe

```text
+------------------------------------------------------------------+
| 주문 입력                                                         |
| 수신된 발주를 등록합니다                                           |
+------------------------------------------------------------------+

[ 주문 기본 정보 ]
+------------------------------------------------------------------+
| 고객명 *                                                          |
| [검색하여 선택...                                    v]           |
|                                                                  |
| 설계번호 *                                                        |
| [____________]  [조회]                                           |
|                                                                  |
| 업체명            품명               규격          부서코드       |
| [자동 입력 ░░░]  [자동 입력 ░░░]   [자동 입력 ░]  [░░]          |
| ※ 설계번호 조회 후 자동 채워집니다                                |
|                                                                  |
| 발주 수량 *        발주 채널 *                                    |
| [________]        [선택...          v]                           |

[ 출하예정일 ]
+------------------------------------------------------------------+
| 예정일              예정 수량                                     |
|-------------------------------------------------------------------
| [날짜 선택 ▾]       [______]                          [삭제]    |
```

### 주문 현황

#### 화면 목적
등록된 전체 주문의 접수~출하 진행 상태를 목록으로 확인하고 관리한다. A는 수정·취소·생산팀 전달을 수행하고, P와 E는 조회 및 상세 진입만 한다.

#### 주요 사용자
- A — Administrative (사무직), P — Production (현장직, 팀장 포함), E — Executive (임원)

#### 화면 구성

**상단**: 페이지 타이틀 + 보조 설명

**중단 — 필터/액션 바**
- 검색 입력 (주문번호, 고객명, 품명)
- 필터 드롭다운: 부서코드 / 진행 단계 / 날짜 범위
- [배치 액션: 생산팀 전달 / 취소] — A, 행 선택 시 활성화
- [주문 입력] CTA 버튼 — A만 노출

**중단 — 데이터 테이블**
- 컬럼: 체크박스 | 주문번호 | 고객명 | 품명 | 규격 | 부서코드 | 수량 | 출하예정일 | 진행 단계 | 전달 여부 | 액션
- 행 클릭 → 주문 상세 진입
- 행 우측 액션(A만): [수정] [취소] [전달]
- 진행 단계: 상태 태그(Tag)로 표시

**하단**: 페이지네이션

#### 포함 컴포넌트 (개념 수준)
- 페이지 타이틀
- Search Input
- Multi-select Dropdown (부서코드 필터)
- Select / DatePicker (진행 단계, 날짜 범위 필터)
- Batch Action Bar (행 선택 시 표시 — 전달, 취소)
- Button — primary (주문 입력, A 전용)
- Data Table (정렬, 체크박스 선택 지원)
- Tag (진행 단계 상태 표시)
- Overflow Menu (행 단위 수정/취소/전달, A 전용)
- Pagination

#### ASCII Wireframe

```text
+------------------------------------------------------------------+
| 주문 현황                                                         |
| 등록된 전체 주문의 진행 상태를 확인합니다                          |
+------------------------------------------------------------------+
| [검색: 주문번호, 고객명, 품명...]  [부서코드 ▾] [진행단계 ▾]    |
| [날짜 범위 ▾]                      [생산팀 전달*] [취소*]        |

+------------------------------------------------------------------+
| ☐ | 주문번호 | 고객명  | 품명    | 규격 | 부서 | 수량 | 출하예정일 | 단계       | 전달 | 액션 ⋮ |
|---|---------|--------|--------|------|------|------|-----------|-----------|------|---------|
| ☐ | ORD-001 | (주)A사 | 제품X   | S-10 | R    | 500  | 04/10     | [생산중]  | ✓    | ⋮      |
| ☐ | ORD-002 | (주)B사 | 제품Y   | M-20 | P    | 200  | 04/15     | [계획중]  | ✓    | ⋮      |
| ☐ | ORD-003 | (주)C사 | 제품Z   | L-30 | S    | 100  | 04/20     | [시작대기]| -    | ⋮      |
|   | ...                                                          |
+------------------------------------------------------------------+
| < 1 2 3 ... >                                    10건 / 페이지 ▾ |
+------------------------------------------------------------------+
  ※ 행 클릭 → 주문 상세 진입
  ※ ⋮ 메뉴: [수정] [취소] [생산팀 전달] — A만 노출
```

### 주문 상세

#### 화면 목적
단일 주문의 전체 정보(주문 내용, 출하예정일, 생산 진행 상태, 출하 실적)를 한 화면에서 확인한다. 주문→생산→출하 흐름의 허브 화면이다.

#### 주요 사용자
- A, P, E (모두 접근, 액션 노출은 역할별 차이)

#### 화면 구성

**상단**: 페이지 타이틀(주문번호) + [← 주문 현황] 브레드크럼 + 역할별 액션 버튼

**중단 — 4개 섹션**

섹션 1: 주문 기본 정보
- 주문번호, 고객명, 설계번호, 품명, 규격, 부서코드, 발주수량, 발주채널, 전달 여부, 등록일시 — read-only 표시

섹션 2: 출하예정일 목록
- 테이블: 예정일 | 예정수량

섹션 3: 생산 진행 상태
- 테이블(생산 작업 행 단위): 작업수량 | 현재 단계 | 담당자 | 변경일시
- 생산 작업은 주문에 직접 연결되며, 출하예정일과 직접 연결하지 않는다.
- 단계는 Tag로 표시

섹션 4: 출하 실적
- 테이블: 예정일 | 예정수량 | 출하 상태 | 출고 완료 수량 | 출고일

**하단**: 고정 액션 바 (역할별)
- A: [← 주문 현황] [수정] [생산팀 전달]
- P: [← 주문 현황] (후속 생산 현황에서 단계 변경)
- E: [← 주문 현황]

#### 포함 컴포넌트 (개념 수준)
- Breadcrumb (← 주문 현황)
- 페이지 타이틀 (주문번호)
- Button — primary / secondary (역할별 액션)
- Section Header (4개 섹션 구분)
- Key-Value Display (기본 정보 필드 — read-only)
- Data Table (출하예정일, 생산 진행 상태, 출하 실적)
- Tag (생산 단계, 출하 상태 표시)

#### ASCII Wireframe

```text
+------------------------------------------------------------------+
| ← 주문 현황                                                       |
| ORD-001 — 주문 상세                    [수정] [생산팀 전달] (A)  |
+------------------------------------------------------------------+

[ 주문 기본 정보 ]
+------------------------------------------------------------------+
| 주문번호   ORD-001        고객명     (주)A사                      |
| 설계번호   DSG-010        품명       제품X                        |
| 규격       S-10           부서코드   R                            |
| 발주수량   500            발주채널   이메일                        |
| 전달여부   전달완료        등록일시   2026-03-25 09:41             |
+------------------------------------------------------------------+

[ 출하예정일 ]
+------------------------------------------------------------------+
| 예정일         예정수량                                           |
|----------------|--------                                         |

| 2026-04-20     200                                               |
+------------------------------------------------------------------+

[ 생산 진행 상태 ]
+------------------------------------------------------------------+
| 예정일     | 예정수량 | 진행 단계    | 담당자  | 변경일시         |
|------------|---------|-------------|---------|----------------|
| 2026-04-10 | 300     | [생산중]    | 홍길동  | 03-27 14:20    |
| 2026-04-20 | 200     | [계획중]    | 이철수  | 03-26 10:05    |
+------------------------------------------------------------------+

[ 출하 실적 ]
+------------------------------------------------------------------+
| 예정일     | 예정수량 | 출하 상태         | 출고수량 | 출고일     |
|------------|---------|-----------------|---------|-----------|
| 2026-04-10 | 300     | [일부 출하 200/300]| 200    | 04-10     |
| 2026-04-20 | 200     | [출하 준비 0/200] | -       | -         |
+------------------------------------------------------------------+

                                              [← 주문 현황]
```

### 생산 현황 (후속 확장, POC 본 구현 제외)

#### 화면 목적
후속 생산 화면에서 생산팀에 전달된 주문의 공정 진행 단계를 현장직이 갱신하고, 전체 생산 진행 상황을 조회한다.

#### 주요 사용자
- P — Production (현장직, 팀장 포함, 단계 변경 가능), E — Executive (임원, 조회만)

#### 화면 구성

**상단**: 페이지 타이틀 + 보조 설명

**중단 — 필터/액션 바**
- 필터 드롭다운: 부서코드 / 진행 단계 / 날짜 범위
- 검색 입력 (주문번호, 고객명, 품명)

**중단 — 데이터 테이블**
- 행 단위: 주문 기준 생산 작업(production task)
- 기본 정렬: 주문 등록일 오름차순
- 컬럼: 체크박스 | 주문번호 | 고객명 | 품명 | 규격 | 부서코드 | 생산작업수량 | 진행 단계 | 담당자 | 액션
- 진행 단계: Tag로 표시
- 행 우측 액션(P만): [단계 변경] — 클릭 시 단계 변경 모달/패널 열림

**하단**: 페이지네이션

#### 포함 컴포넌트 (개념 수준)
- 페이지 타이틀
- Search Input
- Multi-select Dropdown (부서코드, 진행 단계 필터)
- DatePicker (날짜 범위 필터)
- Data Table (정렬 지원, 체크박스)
- Tag (진행 단계)
- Button — primary (단계 변경, P 전용)
- Modal 또는 Side Panel: 진행 단계 변경 UI (Select + 담당자 입력 + 저장)
- Pagination

#### ASCII Wireframe

```text
+------------------------------------------------------------------+
| 생산 현황                                                         |

+------------------------------------------------------------------+
| [검색: 주문번호, 고객명, 품명...]  [부서코드 ▾] [진행단계 ▾]    |

|---|---------|--------|-------|------|------|---------|------------|------|---------|
| ☐ | ORD-001 | (주)A사 | 제품X  | S-10 | R    | 300     | [생산중]   | 홍길동 | [단계변경]|
| ☐ | ORD-001 | (주)A사 | 제품X  | S-10 | R    | 300     | [계획중]   | 이철수 | [단계변경]|
| ☐ | ORD-001 | (주)A사 | 제품X  | S-10 | R    | 400     | [시작대기] | -     | [단계변경]|
|   | ...                                                          |
+------------------------------------------------------------------+

+------------------------------------------------------------------+
※ [단계변경] 클릭 시 → 모달:

  +----------------------------+
```

### 출하 현황 (후속 확장, POC 본 구현 제외)

#### 화면 목적
후속 출하 화면에서 출하 실적을 입력하고, 출하예정일별 진행 상태 및 미출고 현황을 조회한다. 출하 상태는 `delivery_schedules`에서 관리하고, 실제 출고 이력은 `shipment_records`에 기록한다.

#### 주요 사용자
- A (조회), P (실적 입력·조회), E (조회)

#### 화면 구성

**상단**: 페이지 타이틀 + 보조 설명

**중단 — 필터/액션 바**
- 필터 드롭다운: 출하 상태 / 부서코드 / 날짜 범위
- 검색 입력 (주문번호, 고객명, 품명)
- 미출고 빠른 필터 버튼 (출하 준비 + 일부 출하 + 출하 중지 묶음)

**중단 — 데이터 테이블**
- 행 단위: 출하예정 건(`delivery_schedules`)
- 출하 실적은 `shipment_records`가 `delivery_schedules`에 직접 연결된 이력으로 표시
- 컬럼: 출하예정일 | 주문번호 | 고객명 | 품명 | 규격 | 부서코드 | 출하예정수량 | 출하 상태 | 출고수량 | 출고일 | 납기요구일 | 비고 | 액션
- 출하 상태: Tag로 표시 (출하 준비 / 일부 출하 / 출하 완료 / 출하 중지)
- 행 우측 액션(P만): [실적 입력]

**하단**: 페이지네이션

#### 포함 컴포넌트 (개념 수준)
- 페이지 타이틀
- Search Input
- Multi-select Dropdown (출하 상태, 부서코드 필터)
- DatePicker (날짜 범위)
- Button — ghost (미출고 빠른 필터)
- Data Table
- Tag (출하 상태)
- Button — primary (실적 입력, P 전용)
- Modal 또는 Side Panel: 출하 실적 입력 UI (출고일 + 실제출고수량 + 저장)
- Pagination

#### ASCII Wireframe

### 설계 관리

#### 화면 목적
제품/설계 기준 데이터를 조회한다. 설계번호는 주문 입력 시 제품 사양 조회의 키값으로 사용된다.

#### 주요 사용자
- A — Administrative (사무직), E — Executive (임원)

#### 화면 구성

**상단**: 페이지 타이틀 + 보조 설명

**중단 — 필터/액션 바**
- 검색 입력 (설계번호, 품명)
- [신규 설계 입력] CTA 버튼 — POC에서는 클릭 시 추후 개발 예정 Toast 표시

**중단 — 데이터 테이블**
- 컬럼: 설계번호 | 품명 | 규격 | 부서코드
- POC에서는 신규 등록, 수정, 삭제 액션을 제공하지 않는다.

**하단**: 페이지네이션

#### 포함 컴포넌트 (개념 수준)
- 페이지 타이틀
- Search Input
- Button — primary (신규 설계 입력, POC 범위 외 Toast)
- Data Table
- Pagination

#### ASCII Wireframe

## 4. 화면 간 이동 흐름 요약

```
[A: 사무직 흐름]
주문 입력 → (저장) → 주문 현황
주문 현황 → (행 클릭) → 주문 상세
주문 상세 → (수정) → 주문 입력 (편집 모드)
주문 상세 → (생산팀 전달) → 주문 현황 (상태 갱신)
주문 현황 → (배치 선택 후 전달/취소) → 주문 현황 (갱신)

[P: 현장직 흐름]
주문 현황의 생산중 탭 → 주문 상세 (조회)
후속 생산 현황 → (단계 변경 모달) → 생산 현황 (갱신)
후속 출하 현황 → (실적 입력 모달) → 출하 현황 (상태 갱신)

[E: 임원 흐름]
주문 현황 → (행 클릭) → 주문 상세
후속 생산 현황 → (조회, 필터)
후속 출하 현황 → (조회, 미출고 필터)
```
