Order Management UI Specification

⸻

1. Overview

본 문서는 주문 관리 시스템의 UI 구조와 동작 규칙을 정의한다.

PRD에서 정의한 범위와 정책을 전제로 하며, 본 문서는 화면 구조와 상호작용의 최종 UI 기준(Source of Truth)으로 사용한다.

1.1 Design Principles
	•	리스트 중심 구조: 메인 화면은 항상 주문 리스트이다.
	•	Drawer 기반 입력: 주문 생성 및 수정은 우측 슬라이딩 Drawer에서 수행한다.
	•	페이지 전환 없음: 리스트와 입력이 동일 화면 내에서 공존한다.
	•	세로 스크롤 허용: 리스트 및 Drawer 내부 모두 세로 스크롤 가능하다.
	•	상태 기반 관리: 주문은 상태값에 따라 탭으로 분리 관리한다.
	•	접수 탭 중심 작업: 생성, 수정, 취소, 생산팀 전달은 접수 탭에서만 수행한다.
	•	조회 전용 탭 단순화: 생산중, 출하 완료, 삭제됨 탭에서는 불필요한 선택 및 액션 UI를 숨긴다.

1.2 UI / Styling Stack
	•	UI Components: IBM Carbon Design System 사용
	•	Chart / Visualization: Carbon Charts 사용
	•	Styling: Carbon Design System 스타일과 컴포넌트 패턴을 우선 사용
	•	테이블, 모달, 토스트, 폼, 탭, Drawer/Side Panel은 Carbon 패턴을 우선 적용한다.
	•	불필요한 custom CSS 및 custom animation은 사용하지 않는다.
	•	본 문서에 명시되지 않은 레이아웃 영역이나 장식성 UI(예: 배너, 히어로, 소개/요약 카드)는 임의로 추가하지 않는다.

2. Overall Layout Structure

2.1 Main Screen Composition

-------------------------------------------------------------
| + 새 주문                                                  |
|-----------------------------------------------------------|
| [접수] [생산중] [출하 완료] [삭제됨]                      |
|-----------------------------------------------------------|
|                                                           |
|   주문 리스트 영역 (세로 스크롤 가능)                    |
|                                                           |
-------------------------------------------------------------

구성 요소
	1.	좌측 상단: [+ 새 주문] 버튼
	2.	상단 탭: 주문 상태 필터 탭
	3.	중앙: 주문 리스트 테이블
	4.	주문 생성/수정 시: 우측 Drawer 슬라이드 오픈

2.2 탭별 UI 차이
	•	접수 탭: 체크박스, 관리 컬럼, 다중 선택 액션 바 노출
	•	생산중 탭: 조회 전용, 체크박스와 관리 컬럼 숨김
	•	출하 완료 탭: 조회 전용, 체크박스와 관리 컬럼 숨김
	•	삭제됨 탭: 조회 전용, 체크박스와 관리 컬럼 숨김

3. 주문 리스트 페이지

3.1 목적
	•	주문 조회
	•	접수 탭에서 주문 수정
	•	접수 탭에서 주문 취소
	•	접수 탭에서 생산팀 전달
	•	접수 탭에서 다중 선택 작업 수행

3.2 상태 탭 구조

상단 탭 구성:
	•	접수
	•	생산중
	•	출하 완료
	•	삭제됨

동작 규칙
	•	각 탭은 해당 상태의 주문만 표시한다.
	•	기본 진입 탭은 접수이다.
	•	생산팀 전달 시 상태는 `released`로 변경되며, 접수 탭에서는 자동으로 사라진다.
	•	취소는 `cancelled` 상태로 변경되며 “삭제됨” 탭으로 이동한다.
	•	출하 완료 탭은 주문 lifecycle 완료 상태인 `completed` 주문을 조회하기 위한 탭이다.
	•	POC에서는 `completed` 상태 변경 액션을 제공하지 않는다.

3.3 리스트 테이블 구조

접수 탭

---------------------------------------------------------------------------------------------------
| 선택 | 주문번호    | 주문요청일   | 고객사   | 담당자 | 채널 | 납기   | 상태 | 관리            |
---------------------------------------------------------------------------------------------------
| □    | 260315-0001 | 2026-03-15 | 동성전자 | 김영수 | 카톡 | 3/20   | 접수 | 수정 전달 취소 |
---------------------------------------------------------------------------------------------------

조회 전용 탭

-----------------------------------------------------------------------------------------
| 주문번호    | 주문요청일   | 고객사   | 담당자 | 채널 | 납기   | 상태   |
-----------------------------------------------------------------------------------------
| 260315-0001 | 2026-03-15 | 동성전자 | 김영수 | 카톡 | 3/20   | 생산중 |
-----------------------------------------------------------------------------------------

3.4 컬럼 정의
	•	주문번호
	•	주문요청일
	•	고객사
	•	담당자
	•	채널
	•	납기
	•	일반 출하: 날짜 표시
	•	분할 출하: “분할” 표시
	•	상태

접수 탭 전용 컬럼
	•	선택: 체크박스
	•	관리
	•	수정
	•	전달 (생산팀 전달)
	•	취소

3.5 테이블 표시 규칙
	•	모든 컬럼은 데스크톱 기준 고정 너비를 사용한다.
	•	리스트 전체는 고정 폭 컬럼 조합으로 구성한다.
	•	화면이 좁을 경우 테이블 영역에 가로 스크롤을 허용한다.
	•	셀 텍스트는 줄바꿈 없이 한 줄로 표시한다.
	•	컬럼 폭을 초과하는 텍스트는 ellipsis(...) 처리한다.
	•	ellipsis 처리된 값은 hover 시 전체 값을 확인할 수 있어야 한다.

3.6 빈 상태
	•	접수 탭: “접수된 주문이 없습니다.”
	•	생산중 탭: “생산중 주문이 없습니다.”
	•	출하 완료 탭: “출하 완료 주문이 없습니다.”
	•	삭제됨 탭: “취소된 주문이 없습니다.”

3.7 제외 범위
	•	검색 UI 없음
	•	정렬 UI 없음
	•	페이지네이션 없음
	•	필터 UI 없음

4. 리스트 동작 정의

4.1 접수 탭 개별 동작

수정
	•	해당 주문 데이터 로드
	•	우측 Drawer 오픈
	•	수정 모드 진입

전달 (생산팀 전달)
	•	클릭 시 확인 모달 표시
	•	확인 시:
	•	주문 상태를 `released`로 변경
	•	접수 탭에서 자동 제거
	•	생산중 탭에서 조회 가능
	•	Toast 표시

취소
	•	확인 모달 표시
	•	확인 시 상태를 `cancelled`로 변경
	•	삭제됨 탭으로 이동
	•	Toast 표시

4.2 조회 전용 탭 동작
	•	생산중 탭은 조회만 가능하다.
	•	출하 완료 탭은 조회만 가능하다.
	•	삭제됨 탭은 조회만 가능하다.
	•	체크박스를 표시하지 않는다.
	•	관리 컬럼을 표시하지 않는다.

4.3 다중 선택 기능

체크박스
	•	접수 탭에서만 각 행 좌측에 체크박스를 배치한다.
	•	접수 탭 헤더에 전체 선택 체크박스를 제공한다.
	•	전체 선택은 현재 화면에 보이는 행 기준으로 동작한다.

다중 작업 바
	•	1개 이상 선택 시 탭 아래, 테이블 위에 작업 바를 노출한다.

작업 목록
	•	선택 취소
	•	선택 항목 생산팀 전달

다중 취소
	•	확인 모달 표시
	•	선택 항목 상태를 `cancelled`로 변경
	•	Toast 표시

다중 생산팀 전달
	•	확인 모달 표시
	•	선택 항목 상태를 `released`로 변경
	•	접수 탭에서 제거
	•	생산중 탭에서 조회 가능
	•	Toast 표시

제약
	•	다중 수정은 허용하지 않는다.
	•	수정은 항상 개별 “수정” 버튼으로만 가능하다.

4.4 확인 모달
	•	취소와 생산팀 전달 모두 확인 모달을 사용한다.
	•	다중 작업일 경우 선택 건수를 본문에 표시한다.
	•	확인 후 성공 결과는 Toast로 안내한다.

5. 주문 생성 / 수정 Drawer

5.1 기본 구조

----------------------------------------------------
| 주문 입력                                         |
|--------------------------------------------------|
| 1. 주문 접수                                      |
| 2. 고객사 및 담당자                               |
| 3. 제품/설계                                      |
| 4. 납기                                           |
|                                                    |
|                                         [저장]    |
----------------------------------------------------

공통 규칙
	•	우측 슬라이딩 방식
	•	배경 리스트는 비활성화 처리
	•	상단 닫기 버튼 존재
	•	내부 세로 스크롤 허용
	•	생성/수정 동일 UI 재사용
	•	저장 성공 시 Drawer를 닫고 Toast를 표시한다.

5.2 닫기 규칙
	•	닫기 버튼, 바깥 영역 클릭, ESC 입력으로 닫기를 시도할 수 있다.
	•	미저장 변경이 없으면 즉시 닫는다.
	•	미저장 변경이 있으면 확인 모달을 표시한다.

5.3 미저장 변경 확인 모달
	•	문구: “변경사항을 저장하지 않고 닫을까요?”
	•	버튼: [계속 편집] [닫기]

6. Drawer 상세 입력 구성

6.1 주문 접수

주문 요청일   [ YYYY-MM-DD ]

채널
[ 이메일 ]  [ 카톡 ]  [ 전화 ]  [ 기타 ]
(기타 선택 시) 기타 채널  [ _________ ]

주문 담당자 (접수자)
[ 로그인 계정명 ]  (Read-only)

필수 조건
	•	주문 요청일
	•	채널
	•	기타 선택 시 기타 채널

6.2 고객사 및 담당자

고객사 및 담당자  [ 검색 ________ ]  [+ 신규]

검색 대상
	•	고객사명
	•	담당자명
	•	사업자번호
	•	연락처

선택 규칙
	•	반드시 고객사 + 담당자 세트 선택
	•	선택 전 저장 불가

신규 등록 (POC)
	•	UI에는 [+ 신규] 버튼만 표시한다.
	•	버튼 클릭 시 Toast를 표시한다.
	•	Toast 문구: “신규 고객사/담당자 등록 기능은 추후 개발 예정입니다.”
	•	POC 단계에서는 실제 등록 기능을 구현하지 않는다.

6.3 제품/설계 선택

제품/설계  [ 검색 ________ ]  [+ 신규 제품 등록]
--------------------------------------
| 설계번호 | 품명 | 규격 | 부서코드 | 수량 |
--------------------------------------

규칙
	•	주문 1건당 제품/설계는 1개만 선택한다.
	•	선택된 제품/설계는 `orders.design_id`에 저장한다.
	•	수량은 `orders.quantity`에 저장한다.
	•	제품/설계 선택 전 저장 불가

신규 제품 등록 (POC)
	•	UI에는 [+ 신규 제품 등록] 버튼만 표시한다.
	•	버튼 클릭 시 Toast를 표시한다.
	•	Toast 문구: “신규 제품 등록 기능은 추후 개발 예정입니다.”
	•	POC 단계에서는 실제 등록 기능을 구현하지 않는다.

6.4 납기 입력

납기 유형
(● 일반 출하)  (○ 분할 출하)

납기일  [ YYYY-MM-DD ]

분할 출하 선택 시

---------------------------------
| 출하일 | 수량 |
---------------------------------
|        |      |
---------------------------------
[ + 분할 추가 ]

검증 규칙
	•	일반: 납기일 필수
	•	분할:
	•	각 행 출하일 및 수량 필수
	•	분할 합계 = 주문 수량

7. 저장 및 검증

7.1 저장 버튼
	•	Drawer 하단 고정
	•	버튼명: [저장]

7.2 저장 조건
	•	주문 요청일 입력 완료
	•	채널 입력 완료
	•	고객사/담당자 선택 완료
	•	제품/설계 1개 선택 완료
	•	주문 수량 입력 완료
	•	납기 입력 완료
	•	분할일 경우 합계 일치

7.3 오류 처리
	•	오류 필드 강조 표시
	•	상단에 요약 메시지 표시
	•	저장 실패 시 Drawer 유지

7.4 알림 노출 방식
	•	시스템 알림은 Toast Notification 형태로 제공한다.
	•	Toast는 화면 최상위 레이어에 고정 표시한다.
	•	Drawer 또는 확인 모달이 열려 있어도 Toast는 그 위에 보여야 한다.
	•	노출 위치는 뷰포트 상단 중앙으로 고정한다.
	•	사용 예:
	•	저장 성공/실패
	•	생산팀 전달 성공/실패
	•	취소 성공/실패
	•	POC 범위 외 기능 안내 메시지
	•	Toast는 자동으로 사라지며, 사용자가 직접 닫을 수도 있어야 한다.

⸻

8. 상태 흐름 정의

active → released
	•	전달 버튼 또는 다중 전달 시: active → released
	•	취소 시: active → cancelled

기타 표시 상태
	•	출하 완료: 주문 lifecycle 완료 상태인 `completed` 주문을 조회한다.
	•	삭제됨: `cancelled` 주문을 조회한다.

탭별 액션 규칙
	•	접수(active): 수정, 전달, 취소, 다중 선택 가능
	•	생산중: 조회만 가능
	•	출하 완료: 조회만 가능
	•	삭제됨: 조회만 가능
