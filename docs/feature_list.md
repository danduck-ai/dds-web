# Index

## 권한

- **A** — Administrative (사무직)
- **P** — Production (현장직, 팀장 포함)
- **E** — Executive (임원)

## 기능

- **고객 조회**: 등록된 고객 목록에서 고객을 검색하고 선택한다
- **설계번호 조회**: 설계번호를 입력하면 연결된 제품 사양(업체명, 품명, 규격, 부서 코드 등)이 자동으로 불러와진다
- **주문 입력**: 발주 채널(이메일/카카오톡/전화)로 수신된 발주 내용을 웹 화면에 직접 입력한다
- **출하예정일 입력**: 1개 주문건에 대해 출하예정일을 여러 날짜로 나눠 입력한다
- **주문 현황 조회**: 등록된 주문 전체의 접수~출하 진행 상태를 목록으로 확인한다
- **주문 수정**: 등록된 주문건의 내용을 수정한다
- **생산팀 전달**: 선택한 주문건(단일 또는 다중)을 생산팀에 전달한다
- **주문 취소**: 선택한 주문건(단일 또는 다중)을 `cancelled` 상태로 변경한다. 물리 삭제는 하지 않는다
- **공정 진행 상태 변경**: 후속 생산 화면에서 주문의 생산 진행 단계를 변경하고 책임자를 기록한다. 단계: 시작 대기 → 계획중 → 생산중 → 일시중지 → 생산완료
- **생산 진행 현황 조회**: 후속 생산 화면에서 부서별 주문의 생산 진행 단계와 담당자를 조회한다
- **출하 실적 입력**: 후속 출하 화면에서 당일 실제 출고 수량과 출고일을 입력한다
- **출하 현황 조회**: 후속 출하 화면에서 출하일지 항목(업체명, 품명, 규격, 수량, 납기요구일, 실제출고수량 등) 및 기간별 출고 실적을 조회한다. 미출고 현황을 포함한다
- **설계 조회**: 등록된 설계 목록을 조회한다
- **고객 조회**: 등록된 고객 목록을 조회한다

# 참고

## 기능 범위 결정

- 주문 입력은 사무 인력이 웹 화면에서 직접 수기 입력하는 방식으로 정의한다. 이메일/카카오톡/전화로 수신된 발주를 사무 인력이 옮겨 입력하며, 자동 수신·파싱은 POC 범위 외다.
- 부서 코드는 설계도에 종속된 값으로, 설계번호 조회 시 자동으로 불러와진다. 별도 지정 기능이 아니다.
- 생산팀 배분("생산 N팀")과 부서 코드는 같은 개념이다. "생산 N팀" 표현은 사용하지 않고 부서 코드(R/S/P)로 통일한다.
- POC에서는 고객/담당자/제품/설계 기준정보 신규 등록, 수정, 삭제 기능을 제공하지 않는다.
- 고객/담당자 및 제품/설계 기준정보는 기존 데이터 목록에서 조회·선택만 한다.
- 수신 확인(생산팀 acknowledgement)은 독립 기능이 아닌 공정 진행 상태의 첫 단계(시작 대기)로 처리한다.

## 데이터 구조 관련

- 출하예정일은 1개 주문건에 대해 여러 날짜로 분할 입력이 가능하다. 여러 주문건의 예정일을 한 번에 입력하는 경우는 없다.
- POC에서는 생산 작업 레코드를 실제 생성하지 않고, 주문의 생산팀 전달 상태(`released`)까지만 관리한다.
- 생산 현황과 출하 관리는 POC 본 구현 범위가 아니라 후속 확장 화면으로 둔다.
- 후속 생산 현황에서는 생산 작업 단계가 시작 대기 → 계획중 → 생산중 → 일시중지 → 생산완료로 관리된다.
- 후속 출하 현황은 미출고 현황을 포함한다. 별도 미출고 화면은 두지 않는다.

## 권한 설계 관련

- 임원(E)은 모든 조회 기능에 접근 가능하다. 입력·수정·삭제 기능은 접근하지 않는다.
- 사무직(A)은 주문 데이터의 입력·수정·취소와 생산팀 전달을 담당한다. 생산 현황 변경은 접근하지 않는다.
- 현장직(P, 팀장 포함)은 생산 및 출하 실적과 관련된 입력·변경을 담당한다. 주문·설계·고객 데이터의 수정은 접근하지 않는다.
